# Data_Communication
## 역할 분담 및 안내

> 개발 범위와 협업 기준 정리. 메서드명·인자·반환값은 각 파트에서 설계 후 공유. 아래 목록은 구현 예정 사항.

## 1. 과제 개요

**AWS Master가 작업 5,000개를 분배하고, 로컬 Worker 4개가 저장·실패 재시도·P2P 부하 분산을 수행시스템 구축**

| 구분 | 역할 |
|---|---|
| Master | 작업 생성·분배, 실패 재할당, 가상 시간 관리, 결과 집계 |
| Worker | 작업 수신·대기 큐 관리·저장·결과 보고 |
| P2P | 작업이 몰린 Worker에서 여유 있는 Worker로 직접 작업 이전 |
| ACK | 요청 수신 여부를 알리는 확인 응답 |
| 가상 시간 | 실제 대기 없이 계산으로 관리하는 시각 |

## 2. 파트와 우선순위

| 파트 | 담당 | 주요 범위 |
|---|---|---|
| **Master 파트** | 선효 | AWS, Master, 가상 시간, 전체 통합 |
| **Worker 파트** | 왕석 | Worker 실행, 큐, 작업 처리·저장, Worker 통계 |
| **통신·P2P 파트** | 대겸 | 공통 송수신, 로그, Worker 간 작업 이전 |
| 공동 | 전원 | 메시지·시간 규칙, 통합 검증, 제출 문서·영상 |

### 진행 순서

1. **공통 규칙 확정:** 메시지 구성, 시간 계산, 파트 간 메서드 사용법.
2. **공통 통신 제공:** 통신·P2P 파트에서 송수신 기능과 사용 예제 우선 공유.
3. **기본 처리 연결:** Master 배정 → Worker 수신·처리 → 결과 보고.
4. **재시도·P2P 연결:** 실패 재할당, 작업 예약·이전·ACK 처리.
5. **전체 검증:** 5,000개 완료, 통계, 정상 종료, 제출 준비.

**동시 진행 가능 작업:** Master 파트의 데이터 생성·접속 관리, Worker 파트의 큐·저장소 구현.

## 주의 사항 : 초기화 함수는 해당 폴더의 노드 로그 5개를 모두 삭제하므로, 각 실행 환경에서 로거 생성 전 한 번만 호출. Worker마다 호출하면 다른 Worker 로그가 지워질 수 있음.

## 3. Master 파트 — 작성할 메서드의 역할

| 순서 | 구현 내용 |
|---|---|
| 먼저 | 고유 Key·Value 생성 및 원본 보관 |
| 먼저 | Worker 접속·ID·P2P 주소 등록, 중복 ID 확인 |
| 기본 | Worker 4개 준비 완료 확인 및 서로의 접속 주소 공유 |
| 기본 | 큐 상태 조회·분배 대상 선택·작업 전송 |
| 기본 | 수신 확인·거절·처리 결과 반영, 중복 결과 제외 |
| 연동 | 실패 작업 우선 보관 및 다른 Worker 재할당 |
| 연동 | P2P로 변경된 작업 위치·큐 상태 반영 |
| 연동 | 아래 공통 규칙에 따른 가상 시간 진행·이벤트 관리 |
| 마무리 | 고유 성공 5,000개·원본 값 일치 확인 |
| 마무리 | Worker 통계 수집, 전체 KV 출력, 종료 신호·연결 정리 |

**확인 사항**

- 최소 큐 우선 배정, 동률이면 순환 선택.
- 실패 재시도 우선 배정, 직전 실패 Worker 제외.
- 다른 Worker에 공간이 없으면 재할당 대기.
- 전송 중 작업과 큐 보고의 중복 계산 방지.
- 생성 원본과 성공 완료 목록 분리.
- AWS SSH 접속과 별도로 Master 작업 포트의 외부 연결 확인.

## 4. Worker 파트 — 작성할 메서드의 역할

| 순서 | 구현 내용 |
|---|---|
| 먼저 | Worker별 큐·저장소·소켓·통계 초기화 |
| 먼저 | Master 접속·등록 및 독립 Worker 스레드 4개 실행 |
| 기본 | 작업 수신, 큐 용량 확인, 수신·거절 응답 |
| 기본 | 처리할 작업 선택, 처리시간·성공 여부 추첨 |
| 기본 | 성공 저장·실패 기록, 결과·큐 상태 보고 |
| 기본 | 큐 변화·WARN 로그 기록 |
| 연동 | 이전할 작업 예약, 수신 작업 추가, 이전 상태 조회 |
| 연동 | ACK 확인 후 예약 작업 제거, 확실한 거절 시 예약 해제 |
| 마무리 | 대기시간·성공·실패 등 통계 반환 |
| 마무리 | 종료 요청 처리, 로그 저장, 소켓·스레드 정리 |

**통신·P2P 파트에 먼저 공유할 기능:** 큐 상태 조회, 작업 예약·수신·제거·예약 해제 메서드의 사용법.

**확인 사항**

- Worker마다 별도 큐·저장소 사용.
- 처리 중 작업을 제외한 대기 큐 최대 10개.
- ACK 전 송신 예약 작업은 큐 용량에 포함, 처리 대상에서는 제외.
- 큐 확인·수정 시 잠금 적용. 네트워크 응답 대기 중 큐 잠금 유지 금지.
- 재시도에도 성공 80%·실패 20% 동일 적용.
- 처리 중에도 메시지 수신 가능 여부 확인.

## 5. 통신·P2P 파트 — 작성할 메서드의 역할

### 공통 통신·로그 우선

| 순서 | 구현 내용 |
|---|---|
| 먼저 | 소켓 연결별 송신·수신·종료 처리 |
| 먼저 | JSON 메시지 전송, 줄바꿈 기준 메시지 구분 |
| 먼저 | 나뉘어 도착한 메시지 누적, 함께 도착한 메시지 분리 |
| 먼저 | 메시지 필수 정보 검사, 연결 종료·오류 구분 |
| 기본 | 노드별 로그 파일 생성·기록·저장·종료 |
| 기본 | 여러 스레드의 송신·로그가 섞이지 않도록 처리 |

**Master·Worker 파트에 우선 전달:** 송수신 사용 예제, 필요한 입력·반환값, 오류 처리 방식.

### P2P 연동

| 순서 | 구현 내용 |
|---|---|
| 연동 | Worker 간 직접 접속 수신, 이웃 주소 관리 |
| 연동 | 가상 시간 기준 주기적 부하 점검 |
| 연동 | 이웃 큐 조회, 이전 대상·작업 수 선택 |
| 연동 | 작업 예약 요청 → 직접 전송 → ACK 확인 → 송신 큐 제거 요청 |
| 연동 | 이전 상태 조회, 중복 수신 방지, 결과를 Master에 보고 |
| 마무리 | P2P 횟수 집계, 진행 중 이전·연결 정리 |

**확인 사항**

- 큐 수정은 Worker 파트의 메서드를 통해서만 수행.
- 수신 시점에 공간 재확인, 부족하면 거절.
- ACK 미수신만으로 실패 단정·예약 해제 금지. 상대 수신 상태 확인.
- 같은 이전 요청의 재수신 시 중복 추가 방지.
- 소켓 하나당 수신 담당 하나, 동시 송신에는 잠금 적용.

## 6. 공통 규약

### 메시지

- **UTF-8 JSON + 줄바꿈** 사용.
- 메시지 종류, 송신·수신 노드, 고유 메시지 ID, 가상 시각 포함.
- 작업 관련 메시지에 Key·Value·배정 시도 번호 포함.
- 응답에 원래 요청 ID, 이전 메시지에 고유 이전 ID 포함.
- 재배정 시 시도 번호 갱신, P2P 이전 시 Key·Value·시도 번호 유지.
- 접속·준비·배정·수신 확인·결과·큐 조회·이전·시간 제어·종료 메시지 필요.
- **구체적인 메시지 이름·필드·메서드 형식은 통신·P2P 파트 초안 공유 후 공동 확정.**

### 가상 시간 — 공통 구현 기준

**Master가 전역 가상 시간 관리. 아래는 구현 기준이며, 현재 코드의 구현 완료를 의미하지 않음.**

| 항목 | 규칙 |
|---|---|
| 시작·진행 | 0초 시작. 실제 시간·sleep 대신 처리·통신 비용을 순서대로 누적. 병렬 작업의 비용도 합산 |
| 작업 처리 | 매 시도 랜덤 1~3초. 성공·실패 모두 반영 |
| 통신 | 노드 간 메시지 편도 1초, 요청·응답 합계 2초. P2P·관리·종료 메시지도 포함 |
| 중복 방지 | 같은 전송의 송신·수신 보고는 메시지 ID로 묶어 한 번만 집계. 요청과 ACK는 별개 전송 |
| 이벤트·로그 | 큐 진입 → 처리 시작 → 처리 완료 → 결과 보고 순서 보장. Master가 확정한 이벤트 시각으로 기록 |
| P2P 점검 | 공통 가상 시간 기준 랜덤 1~3초 간격. 대기 작업 수 × 2초 > 15초이면 이전 시도 |
| 종료 | 5,000개 성공 시각은 작업 완료 시각. 진행 중 이전 정리·종료 확인 통신까지 반영한 값은 전체 수행시간 |

**파트별 연결 순서**

1. **Master 파트:** 시간 갱신·P2P 점검 시각 관리, 이벤트 시각을 전달할 메시지 형식 공유.
2. **Worker 파트:** 큐 진입·처리 시작·처리시간 정보 제공, 확정 시각으로 대기시간·통계 계산. 별도 시계 증가 금지.
3. **통신·P2P 파트:** 메시지 ID·시각 전달, Worker 간 직접 통신 내역 보고. 시간 정보는 가능한 기존 메시지에 포함.
4. **통합 확인:** 늦게 도착한 보고로 이벤트 순서가 뒤집히거나 P2P 점검이 누락되지 않는지 확인.

메시지 필드·호출 방식은 Master 파트에서 공유 후 연결. 각 파트나 Codex 작업에서 별도 시간 규칙 추가 금지.

### 큐·P2P

- 큐 수정 담당은 Worker 파트로 통일.
- 이전 예약 작업의 중복 처리 방지.
- **예약 → 직접 전송 → 수신 큐 추가 → ACK → 송신 큐 제거** 순서 적용.
- 수신 여부 미확정 작업은 임의 복제·완료 처리 금지.
- 팀 기본안: 최소 큐 Worker 선택, 큐 차이의 절반을 수신 공간 이내로 이전.
- 상대가 없거나 이전할 작업이 없으면 다음 점검에서 재확인.
- 알고리즘 변경 시 파트 간 공유 및 문서 갱신.

## 7. 필수 조건·검증

| 항목 | 확인 기준 |
|---|---|
| 환경 | AWS 등 외부 Master, 로컬 Worker 4개 독립 스레드 |
| 통신 | Master↔Worker, Worker↔Worker 모두 TCP |
| 데이터 | 고유 4자리 16진수 Key 5,000개, Value 1~100 |
| 시작 | Worker 4개 연결·초기화 후 분배 |
| 큐 | 최대 10개, 가득 찬 큐의 추가 요청 즉시 FAIL |
| WARN | 큐 70% 초과 상태에서 입출력마다 반복 기록 |
| 처리 | 가상 1~3초, 매 시도 성공 80%·실패 20% |
| 재시도 | 실패 작업을 다른 Worker에 최우선 재할당, 성공까지 반복 |
| P2P | 가상 1~3초마다 점검, 대기 작업 수 × 2초 > 15초이면 이전 시도 |
| 시간 | 노드 간 가상 지연 1초, 모든 이벤트에 가상 시각 기록 |
| 완료 | 고유 성공 5,000개, 원본 Value 일치, 중복·유실 없음 |
| 종료 | 전체 KV·통계 저장, 진행 중 작업·이전 및 소켓·스레드 정리 |

**외부 서버·소켓·독립 스레드 미충족, 압축 오류, 컴파일·실행 불가는 원문상 전체 0점 조건.**

### 로그·통계

```text
[clock] NODE | EVENT | STATUS | message
```

- STATUS: INFO / SUCCESS / FAIL / WARN.
- 로그: Master.txt, Worker1.txt~Worker4.txt.
- 모든 EVENT·메시지 설명: AllDefinedLogs.txt.

**필수 통계 6개:** Worker별 처리량, 성공·실패 횟수, 평균 대기시간, P2P 이벤트 횟수, 장애 재할당 횟수, 가상 전체 수행시간.

- 처리량은 성공 KV 수 기준. 전체 고유 성공 합계 5,000개 확인.
- 확률 실패와 큐 초과 거절 별도 집계.
- 평균 대기는 큐 진입~처리 시작의 가상 시간 기준. P2P 이전 전 대기 보존, 이동 시간 제외.
- 전체 평균은 대기시간 합계 / 처리 시작 횟수로 계산.
- 실패 후 재시도는 새 처리 시도로 집계. P2P 이전은 같은 시도의 대기시간을 이어서 누적.
- P2P 이벤트는 고유 이전 ID로 중복 제거. 작업 3개를 한 번에 이전하면 이벤트 1회.
- 장애 재할당은 처리 실패로 다른 Worker가 수락한 재배정 기준.
- 각 노드 최종 STAT에 관련 지표 기록, Master에서 전체·Worker별 집계.
- Worker 통계에 집계 기준 시각 포함. 종료 확인까지의 전체 수행시간은 Master에서 최종 집계하며 작업 완료 시각과 구분.

**원문 예시 주의:** 통계는 5개가 아닌 6개. 예시 수행시간·성공 건수 복사 금지. 실제 5,000개 성공 결과로 검증.
