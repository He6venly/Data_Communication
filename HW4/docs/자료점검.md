# 제공 자료 점검 기록

2026-10-27 기준. 최초 제공 파일은 배포팩 88개 + 루트 파일 5개 = 93개다.

## 범위와 검증 한계

- 공식 명세 15쪽·강의자료 120쪽 전체 텍스트 확인. canvas 요구 페이지는 렌더링해 도표와 예시도 대조했다.
- Python·Java·C의 키트와 도구 소스를 검토했다. 원본은 변경하지 않았다.
- 모든 배포 텍스트를 읽고, 판 파일은 전체 바이트·행 폭·LF·문자를 검사했다.
- G11 round 31개는 실제 SHA-256 앞 8자리와 N=1/6/7 기록을 대조했다. hash_result의 TEAM·머리줄·31줄·FINAL·TOTAL도 대조했다.
- 작은 띠 세 개의 정답을 연결하면 Rule1 R1과 일치하고 Rule3 R10은 입력과 일치한다.
- GIF 두 개는 바이트가 같으며 각각 301프레임·1000×830. 전 프레임 디코딩 및 단계별 대표 화면 확인.
- PEM은 서버 접속 비밀키이므로 존재만 확인하고 내용을 읽지 않았다. 서버 접속은 수행하지 않았다.
- 규칙 함수 구현·3,000회 재계산·Java/C 컴파일·원격 실행을 수행했다는 의미는 아니다.

## 발견한 주의사항

- myrules는 완성 라이브러리가 아니다. rule1/2/3_cell·repaint·to_brian·to_cyclic을 구현해야 한다.
- rule_test 기본 실행은 tests.txt의 규칙 10개만 검사한다. 덧칠·변환·띠 모드는 따로 실행한다.
- check_canvas는 문구 내용·높이·그림 간 배치를 판정하지 않는다.
- 도구의 종료 코드 0은 PASS 보장이 아니다. 출력과 실제 파일을 확인한다.
- make_hash_result는 N의 범위·서로 다름을 보장하지 않는다. 별도 검사 필요.
- make_gif는 입력 frame 누락을 모두 엄격히 거부하지 않는다. 생성 전 301개 이름과 형식, 생성 후 실제 GIF 프레임 수를 검사한다.
- hash.bat은 인자 경로를 인용하지 않아 공백 포함 경로에 취약하다. 파일 전체 SHA-256 앞 8자 계산은 Python hashlib로 통일하는 안을 제안한다.
- 강의자료 57쪽의 밝기표 설명에 공백이 포함되어 보이는 표현이 있지만 같은 쪽 예시·주의와 공식 명세 5쪽은 공백도 변환 대상으로 명시한다. 공백은 식으로 변환한다.
- 저장과 다음 Round 신호의 서술 순서는 설명마다 다소 다르다. 공식 Barrier 의사코드처럼 Lock 안에서 독립 snapshot을 만든 뒤 Lock 밖에서 저장하면 덧칠 전 S(1000)/S(2000)을 보존할 수 있다.
