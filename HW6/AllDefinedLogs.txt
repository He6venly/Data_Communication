1. 공통 형식
----------------------------------------------------------------

  {"t":프로그램시작후초,"peer":"노드","ev":"이벤트",...}

  저장 파일 : logs/tracker.jsonl, logs/P1.jsonl~logs/P4.jsonl.
  인코딩    : UTF-8, 한 줄에 JSON 객체 하나, 줄 끝 LF.
  t         : 각 프로그램 시작 후 단조 시계 기준 초. 숫자.
  peer      : tracker 또는 env의 Peer id. 공개 env는 P1~P4.
  ev        : 아래 이벤트 이름. 문자열.

  이벤트마다 flush하며 EXIT 뒤 추가 이벤트를 기록하지 않음.
  공통 필드 t·peer·ev를 상세 필드로 덮어쓰지 않음.
  파일·id·오류·정책은 문자열, 수량·번호는 정수, 시간·진행률·MiB는
  숫자, HASH의 ok와 Tracker EXIT의 alldone은 JSON 불리언임.
  값이 없으면 null, 목록·사전은 JSON 배열·객체로 저장함.

  1 KB=1,024 B, 1 MiB=1,048,576 B임. idx는 0부터 시작함.
  report.json의 시각은 네 Peer 참가가 모인 Tracker START 기준임.
  JSONL의 t와 report 시각을 같은 기준으로 직접 비교하지 않음.


2. Tracker 로그 - logs/tracker.jsonl
----------------------------------------------------------------

  START_PROGRAM
    env: env.name.
    CLI·env 검사를 통과하고 로그를 연 뒤 첫 이벤트로 기록함.

  JOIN
    id: 참가 Peer. n: 처음 참가한 Peer 수. src_ip: 접속에서 본 IP.
    해당 id의 첫 HELLO를 처리할 때 기록함.

  START
    peers: env 피어 수. 공개 env는 4.
    네 Peer의 첫 HELLO가 모여 실험 START 기준을 고정할 때 기록함.

  REJOIN
    id: 다시 HELLO한 Peer.
    이미 참가한 Peer의 재연결 HELLO를 처리할 때 기록함.

  BACK
    id: DEAD 뒤 유효 메시지를 보낸 Peer.
    생존 상태를 되살릴 때 기록함.

  REGISTER
    id: 완성 보유 Peer. file: 파일 이름.
    env의 port·size·chunk와 일치하는 REGISTER를 처리할 때 기록함.

  CMD
    target: 지시 대상. cmd: DISCONNECT 또는 DESTROY.
    sec: DISCONNECT의 침묵 시간, 초.
    progress: DESTROY를 pending에 넣을 때 전체 진행률.
    지시를 pending에 넣은 시각에 기록함. 실제 전달과 구분함.

  CMD_DELIVERED
    id: 지시 대상. cmd: 실제 응답 한 줄(CMD DISCONNECT sec 등).
    소켓 송신 성공 콜백에서 실제 전달을 확정할 때 기록함.

  CMD_DROPPED
    id: 대상 Peer. cmd: 버린 지시의 응답 한 줄.
    전체 종료 확정·희생자 파괴 뒤 필요 없어진 지시를 버릴 때 기록함.

  DEAD
    id: 죽은 것으로 판정한 Peer. silent_sec: 마지막 유효 메시지 후 초.
    dead_sec를 초과한 첫 생존 판정에서 기록함.

  REPLICATED
    file: 파일 이름. t_start: Tracker START 기준 최초 복제 관측 초.
    upstat: 마지막 원본 REPORT의 [sent, distinct], 미보고 시 null.
    sent는 송신 청크 횟수, distinct는 송신한 서로 다른 idx 수임.
    progress: 관측 시 전체 진행률.
    원본 제외 fresh live bitmap OR가 처음 모두 1일 때 기록함.

  ALL_REPLICATED
    t_start: 모든 파일 복제 관측 시 Tracker START 기준 초.
    p_rep: 그 시점의 전체 진행률.
    모든 파일의 REPLICATED가 처음 확보되었을 때 기록함.

  DONE
    id: 완료 보고 Peer. kind: FULL 또는 PARTIAL.
    detail: FULL은 빈 문자열. PARTIAL은 file:유실수 또는 file:FAILED.
    첫 DONE 또는 기존 DONE 내용이 달라진 때 기록함.

  UNDONE
    id: 완료 상태를 취소한 Peer.
    기존 DONE을 지울 때 기록함.

  BYE
    id: 정상 퇴장 메시지를 보낸 Peer.
    처음 BYE를 처리할 때 기록함. destroy 희생자는 보내지 않음.

  ALLDONE
    live: 살아 있는 Peer id 배열.
    done: 완료 보고 id를 kind에 대응한 객체.
    참가 완료 후 live 전원이 DONE인 최초 판정에서 기록함.

  ABORT
    reason: deadline·stalled·interrupted·server_error 등 중단 사유.
    progress: 중단 시 전체 진행률.
    처음 중단 상태를 고정할 때 기록함.

  ERROR
    error: 예외 문자열. operation: report 저장 실패일 때 report.
    Tracker 실행·report 오류를 처리할 때 기록함.

  EXIT
    code: 실제 종료 코드. alldone: 전체 완료 여부.
    t_exit: 최종 report의 START 기준 종료 초, 기준이 없으면 null.
    서버·handler·주기 스레드 정리와 report 저장 뒤 마지막으로 기록함.


3. Peer 로그 - logs/P1.jsonl~logs/P4.jsonl
----------------------------------------------------------------

  START
    env: 읽은 env 경로. policy: 실제 적용한 random 또는 rarest.
    up_kbps, down_kbps: env의 방향별 속도 한도, KB/s.
    run, seed, description: env의 실행 식별·설명.
    rng_seed: policy_seed + Peer 번호. tracker: 실제 접속 host:port.
    원본 검사 전에 첫 이벤트로 기록함.

  GET
    file: 받을 파일 이름. chunks: 전체 청크 수.
    파일을 처음 수신 준비한 뒤 한 번 기록함. 청크별 GET과 구분함.

  RECV
    file: 파일 이름. idx: 받은 청크 번호. src: 실제 송신 Peer.
    FileStore가 청크를 쓰고 bitmap을 1로 공개한 뒤 기록함.
    마지막 청크도 HASH보다 먼저 기록함. 원본 보유분은 RECV로 세지 않음.

  HASH
    file: 파일 이름. ok: 전체 SHA-256 일치 여부.
    sec: 해시·완성 처리에 걸린 초.
    수신 파일 전체 검증 뒤 기록함. 단순한 청크 길이 검사가 아님.

  CORRUPT
    file: 파일 이름. tries: 해당 파일의 연속 해시 실패 횟수.
    action: 첫 실패는 redownload, 두 번째 실패는 give_up.
    HASH ok=false 뒤 재수신 또는 FAILED 전환을 기록함.

  COMPLETE
    file: 파일 이름. sec: Peer 프로그램 시작 후 초.
    sources: 해당 파일 수신 시도에서 {송신 Peer: 수신 청크 수}.
    해시 성공 후 Tracker REGISTER의 OK를 받은 뒤 한 번 기록함.
    원본 초기 보유는 COMPLETE로 세지 않음.

  FAIL
    file, idx: 요청 대상. src: 상대 Peer. err: 실패 원인 문자열.
    원격 GET의 오류·EOF·timeout·잘못된 DATA를 기록함.
    자체 crash·종료에 따른 취소와 로컬 저장 오류는 포함하지 않음.

  BAN
    target: 일시 제외할 Peer. sec: 제외 기간, 초.
    env의 연속 실패 한도에 도달했을 때 기록함.

  CRASH
    sec: Tracker가 지시한 침묵 시간, 초.
    신규 요청을 막고 저장소·연결을 정리한 뒤 기록함.

  REJOIN
    추가 필드 없음.
    침묵 시간 뒤 저장소·업로드 재개, HELLO·재등록·캐시 갱신을 마친 뒤.

  DESTROY
    추가 필드 없음.
    Tracker의 영구 파괴 지시를 받아 결과를 정리하기 전에 기록함.

  STALLED
    file: 파일 이름. lost: 미보유 청크 수.
    받을 곳이 없는 상태가 stall_sec 지속되어 파일 상태가 바뀔 때.

  UNSTALLED
    file: 파일 이름.
    STALLED 파일에 받을 소스가 다시 생겨 DOWN으로 바뀔 때 기록함.

  DONE
    kind: FULL 또는 PARTIAL. detail: FULL은 빈 문자열.
    PARTIAL detail은 file:유실수 또는 file:FAILED를 공백으로 나열함.
    Tracker가 DONE에 OK를 보낸 뒤 기록함.

  UNDONE
    추가 필드 없음.
    완료 조건이 달라져 UNDONE에 OK를 받은 뒤 기록함.

  ALLDONE
    done: 완료 보고 수. alive: 살아 있는 Peer 수.
    Tracker STATE의 ALLDONE을 확인한 뒤 기록함.

  ABORT
    reason: Tracker 중단 사유, tracker_lost 또는 interrupted.
    silent_sec: Tracker 무응답 초. 무응답 중단이 아니면 0.
    최종 정리를 시작할 중단 사유를 기록함.

  ERROR
    kind: config·local_io·contract·shutdown.
    operation: 실패한 작업. file: 관련 파일 또는 null.
    message: 예외 문자열.
    공유 예외의 종류·작업·파일을 보존해 로컬 실패를 기록함.

  EXIT
    code: 0=ALLDONE, 1=설정·원본 오류, 2=중단·실행 오류, 3=희생자.
    up_mb, down_mb: 전체 성공 송신·수신 commit 누적 바이트 / 2^20.
    하위 구성요소·스레드 정리와 결과 저장 뒤 마지막으로 기록함.
